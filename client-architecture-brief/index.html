01 / Problem

Publishing works. Reading does not.

The customer already manages partner enablement and product literature in Box. The gap is the experience between those files and the people who need them.

Customer

Helios Controls

A commercial HVAC and controls manufacturer that sells through authorized distributors. Engineers need public specifications; partners also need pricing, battlecards, and installation guidance.

Current stack

Box plus a portal

Box already handles authoring, file versions, collaboration, DLP, retention, and audit. The reading surface is a folder tree or a release-bound site that is difficult to change safely.

Pain and impact

Two jobs are coupled

A document correction can wait on a site release. A navigation change can become a production event. Partners spend time hunting for current material, while the business risks stale guidance or confidential material reaching the wrong audience.

Design goal: separate the content clock from the website clock. Authors publish an article in Box; product teams release the shell on Vercel.

READERS → GATE → CACHED BODY

What stays outside Vercel

Source files, Box permissions, content versions, audit history, DLP, retention, and the enterprise identity provider remain in Box or the customer’s identity platform. Markdown renditions may be cached on Vercel, and PDFs stream through a Vercel Function after the gate; neither becomes a second source of truth.

The permission boundary

The gate runs on every partner request as the reader. Only after Box confirms access does the app read the shared article body. Unknown and forbidden articles both return 404, so the site does not disclose that restricted material exists.

Trade accepted: the portal depends on Box at request time for partner authorization. That extra network call preserves one permission system and avoids copying collaborations into an application database.
03 / Vercel

Three primitive families, each with one job.

The solution uses Vercel where it changes the customer experience or the release path. It does not move Box responsibilities into the application.

1Next.js Cache Components

Fast shell, current articles

The shell and article bodies can be cached independently. A Box webhook invalidates the tag for the file that changed, so one edit does not rebuild the site.

Trade-off
Permission checks cannot share the article cache. The gate stays dynamic, adding a Box call to partner requests.

2Preview + Rolling Releases

Review, canary, and roll back

Each code change gets a reviewable Preview URL. On Vercel Pro, production traffic can then move from a small canary to the full release while the prior deployment remains available.

Trade-off
Canary traffic requires an eligible plan and useful telemetry. Preview is only isolated when it uses a separate Box library and credentials; that production control still needs to be developed.

3AI SDK + AI Gateway

Compose grounded answers

Box search and Box AI retrieve only from files the reader can open. AI Gateway runs the writer model, centralizes spend, and provides a fallback model. Answers cite portal paths rather than Box links.

Trade-off
The answer path depends on Box and a model provider. A fallback improves availability, not factual accuracy; responses remain uncached and need citation review.

Deliberately excluded: Vercel Blob and a vector database would create another corpus copy and permission problem. Workflows fits a future scheduled digest or approval process, not the request-scoped ask experience.

05 / Rollout

Validate access first. Move traffic last.

The release sequence treats a permission error as a stop condition. Content publishing and application deployment keep separate rollback paths.

Preview

Isolate

Deploy each application change to a Preview URL. Use a preview Box library and test identities before production onboarding.

Validation

Prove the gates

Run public, limited-partner, and full-partner journeys. Confirm forbidden routes return 404 and ask never cites inaccessible material.

Canary

Observe

Send 5% of production traffic to the new deployment on Vercel Pro. Watch errors, latency, Box failures, and answer quality.

Cutover

Promote

Increase traffic in agreed steps after the acceptance checks pass. Keep the previous portal available during the transition window.

Rollback

Separate the clocks

Restore the prior Vercel deployment for a site defect. Restore or upload a Box file version for an article defect. Use manual cache revalidation if webhook delivery is delayed.

Technical outcomes
  • Track page latency and Box dependency errors by audience.
  • Measure webhook receipt, signature failures, duplicate handling, and cache refresh time.
  • Run access and grounded-answer checks before each release.
Business outcomes
  • Reduce time for a partner to find the current article.
  • Reduce support requests for links, versions, and access.
  • Increase successful self-service sessions and repeat partner use.
  • Shorten review time for website changes through Preview URLs.

Business targets need a current-state baseline; they are not inferred from the demo.

07 / Risks

What we would settle before kickoff.

The demo proves the core boundaries. Production still needs identity, environment, recovery, and operating decisions.

High

Production identity is not the demo login. Replace the JSON account map with enterprise SSO and map the signed-in person to the correct Box identity. Test token lifecycle and deprovisioning.

High

Preview and production currently share a library. Separate folders and credentials so unreleased articles cannot appear in a Preview or production catalog at the wrong time.

High

Availability depends on Box. The permission gate cannot safely fail open. Agree on the customer-facing response and recovery objective for Box outages.

Medium

Webhook delivery needs catch-up. Signed delivery and duplicate handling are implemented; production should reconcile missed events through the Box Events API.

Medium

AI answers remain probabilistic. Retrieval is permission-scoped, but generated wording can still be incomplete or wrong. Keep citations visible, test high-risk questions, and define an escalation path.

Scope

The first release is intentionally narrow. Multi-enterprise tenancy, OCR, translation, self-service partner administration, and scheduled digests are not part of the current build.

08 / Tooling

Agents accelerated delivery. Tests held the boundary.

The build used Cursor as the IDE and coding-agent workspace. Architecture decisions, repository rules, focused tests, and manual review constrained the implementation.

Development workflow

Cursor + repository guidance

Agents helped inspect the codebase, draft implementation slices, write tests, and verify changes. The repository records domain terms and non-negotiable behavior in CONTEXT.md and accepted architecture decisions, so generated code is checked against the same constraints as human-written code.

Validation uses TypeScript, ESLint, Vitest, production builds, and a live browser walkthrough. The current regression suite contains 49 passing tests across 12 test files. Changes are reviewed in Preview before production promotion.

AI behavior validation

Small, permission-aware regression set

Public
“What is the Pulse Controller?” must cite a public portal path and must not reveal partner pricing or multipliers.
Partner
“How do we handle Acme?” for an authorized partner must cite a battlecard or competitive article and stay inside the library.
Access
A logged-out reader and a public-only account must receive 404 for a partner article. A limited partner may open battlecards but not pricing.
Failure
With the primary writer unavailable, the fallback model must use the same tools and permission boundary. No application rewrite or broader retrieval is allowed.
Review
For each sampled answer: verify the claim against its citation, confirm the citation resolves, check audience, and reject unsupported pricing, product, or access claims.
Release rule: any cross-audience disclosure, inaccessible citation, or partner route returning 200 to an unauthorized reader blocks promotion.
